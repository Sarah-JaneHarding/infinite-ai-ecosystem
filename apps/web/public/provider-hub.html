Groq Ecosystem Mastery

  1. 01
    LPU vs GPU — Why Groq is Different
    ▶

    Groq does not train models — it runs open-source models on custom LPU hardware. The LPU's deterministic memory access eliminates the stochastic latency of GPU inference. For teaching tools, this means a teacher gets a response in under 200ms, not 2–5 seconds. The tradeoff: fewer models available than a general cloud provider.

  2. 02
    Model Migration — From llama-3.3 to gpt-oss-120b
    ▶
    Immediate Action Required

    llama-3.3-70b-versatile was retired 16 August 2026. Any request to this model ID returns a 404. Update the gateway config now.

    Migration
    # Old (RETIRED — do not use) GROQ_MODEL_ID=llama-3.3-70b-versatile # New GROQ_MODEL_ID=openai/gpt-oss-120b
  3. 03
    OpenAI-Compatible API — Zero Code Change
    ▶

    Groq's API is a drop-in replacement for the OpenAI Chat Completions endpoint. Change only the baseURL and API key — the request/response shape is identical. The gateway's Groq adapter is already implemented; only config changes are needed for model updates.

  4. 04
    Rate Limit Headers — Proactive Backoff
    ▶

    Groq returns x-ratelimit-remaining-requests, x-ratelimit-remaining-tokens, and x-ratelimit-reset-requests headers on every response. The gateway's rate-limit middleware should read these and queue requests rather than hitting 429 errors. Implement exponential backoff with jitter for retries.

  5. 05
    Batch API — Overnight Curriculum Generation
    ▶

    Groq's Batch API processes requests asynchronously at 50% of the synchronous price. Schedule bulk curriculum map generation for overnight processing at the start of each term. Submit a batch job via POST /v1/batches, poll for completion, then write results to the Brain's curriculum memory tier.

  6. 06
    Spend Limits & Cost Monitoring
    ▶

    Set a monthly spend limit in the Groq console. The gateway's cost ledger tracks per-tenant token spend and writes to audit_event on every model call. Alert when a tenant exceeds 80% of their provisioned budget — before they hit the hard limit mid-lesson.

  7. 07
    Qwen on Groq — the Dual-Provider Pattern
    ▶

    Qwen models are available on Groq's infrastructure. This means a school choosing Qwen as its provider can still get LPU speed without a separate Alibaba Cloud account. Set GROQ_MODEL_ID=qwen-2.5-72b-instruct to use Qwen via Groq. This is currently the recommended Qwen deployment path for South African schools due to data sovereignty considerations.

LM Studio Ecosystem Mastery

  1. 01
    LM Studio Architecture — GUI + Headless
    ▶

    LM Studio Desktop (GUI): Download from lmstudio.ai. Browse and download models from HuggingFace directly in the app. Chat with models, manage VRAM allocation. llmster (headless daemon): The CLI mode for server deployments — starts the API server without the GUI, suitable for the school's AI server. lmstudio CLI (lms): Script model downloads, server management, and config from the terminal.

  2. 02
    VRAM Budgeting — Choosing the Right Quantisation
    ▶

    Quantisation reduces model precision to fit in less VRAM. Q4_K_M is the sweet spot: 4-bit quantised with medium quality loss, roughly 4× smaller than FP16. Q8 is higher quality but requires 2× more VRAM. Always leave 2–3GB of VRAM headroom for the OS and KV cache. The LM Studio GPU usage bar shows live VRAM utilisation.

  3. 03
    OpenAI & Anthropic-Compatible Server
    ▶

    LM Studio's local server exposes http://localhost:1234/v1 with the OpenAI Chat Completions API. It also supports the Anthropic Messages API format. The INFINITE-AI gateway can point to this endpoint with LM_STUDIO_BASE_URL=http://localhost:1234/v1 — no code changes required. JIT (Just-In-Time) loading automatically loads a model into VRAM when first requested and unloads it when idle.

  4. 04
    Structured Output & JSON Schema
    ▶

    LM Studio supports constrained generation with JSON Schema — the model is forced to produce output matching a specified schema. Pass the Zod-derived JSON Schema in the response_format field. This guarantees the curriculum map JSON matches the expected structure, eliminating post-hoc parsing failures.

  5. 05
    lmstudio-js SDK
    ▶

    The lmstudio-js SDK gives richer control than raw HTTP: model lifecycle management, streaming with proper TypeScript types, and direct VRAM statistics. Install via pnpm add lmstudio-js in the gateway package. Record in docs/DEPENDENCIES.md.

  6. 06
    Load-Shedding Resilience Strategy
    ▶

    For South African schools affected by load-shedding: run LM Studio on a machine with UPS backup. The gateway should detect when the cloud provider is unreachable (timeout > 5s) and automatically failover to the local LM Studio endpoint. Implement a health-check ping against both endpoints on startup.

  7. 07
    Model Updates & Maintenance
    ▶

    New model versions appear on HuggingFace regularly. Schedule quarterly model reviews — download the latest quantised version of your chosen model, test it against the INFINITE-AI eval set, then swap the LM_STUDIO_MODEL_ID config. Old model files can be deleted from LM Studio's model library to reclaim disk space.

SASAMS Beta

South African Schools Administration & Management System — the national platform used by most DBE-registered government schools for learner records and class administration.

SA Admin CSV Import / SASAMS API
INFINITE-AI integration
Reads: Learner roll (de-identified to anonymous IDs) · Class structures · Subject allocations · Year-group demographics (aggregated)
Writes: Nothing — read-only · POPIA risk: High (source contains learner PII)
Setup Steps
  1. Contact your school's EMIS officer to obtain export credentials or a DBE data-sharing agreement reference number.
  2. In SASAMS: go to Reports → Export → Learner Data and export as CSV for the current academic year.
  3. In INFINITE-AI: Admin Panel → Integrations → SASAMS → Upload CSV — the system strips names before import.
  4. Verify the preview shows no learner names — only anonymous IDs and class codes — before confirming the import.
  5. For API access (automated monthly pull), a signed DBE Data Sharing Agreement must be on file with your circuit manager first.
  6. Schedule recurring monthly re-imports under Admin Panel → Integrations → SASAMS → Schedule.
