AI Provider Setup Guide for Teachers & Administrators

This guide walks you through connecting all 8 AI providers to your school's INFINITE-AI Brain. You don't need to be a programmer — just follow the steps for the providers your school has chosen, and the system handles the rest.

🇿🇦 South African Schools ✅ POPIA Compliant 8 Providers Supported 🔒 No Learner PII in Prompts
💡 How it works: INFINITE-AI routes every AI task through its Model Gateway — think of it as a traffic controller. You add your provider keys once, and the system automatically tries each provider in order. If one is down or over quota, it falls back to the next one. Teachers never need to think about this.
🔐 Privacy first: No learner names, EMIS numbers, or identifying information ever leave your school's system in an AI prompt. The INFINITE-AI De-identification Service strips all personal data before any model sees it. This is enforced in code — there is no way to bypass it.
§ 01

Which Provider Should Your School Use?

You don't need all 8. Start with Anthropic + Groq for most schools. Add more if you have specific needs.

Your situation Best choice Why
Starting out, want the best quality Anthropic (Claude) Highest reasoning quality for curriculum planning and reports
Need fast screening of many learner files Groq Up to 10× faster than other cloud providers; small screening tasks
Use Google Workspace / need multilingual Google Gemini Integrates with Google docs; strong on African languages
School has Afrikaans or multilingual learners Qwen (Alibaba) Top multilingual performance; DashScope free tier available
Slow or unreliable internet connection Ollama (Local) Runs entirely on your school server — no internet needed once set up
Teachers want to explore models locally LM Studio (Local) Easy GUI app; run models on a laptop, full privacy
School uses Microsoft 365 / Teams Azure OpenAI Covered by school's Microsoft agreement; familiar compliance posture
Need general-purpose GPT-4 capabilities OpenAI Wide model range; strong tool-use for complex workflows
§ 02

Which Provider Handles Which Task?

The gateway tries providers in this order. It skips any that are not configured or are temporarily unavailable.

Task Primary → Fallbacks Used by
curriculum.map Anthropic → Gemini → Qwen → OpenAI → LM Studio → Ollama Curriculum Engine (MOD-01)
toolbox.generate Anthropic → OpenAI → Gemini → Groq → Azure → LM Studio → Ollama Teaching Toolbox (MOD-04)
toolbox.adapt Anthropic → Groq → OpenAI → Gemini → LM Studio → Ollama Teaching Toolbox (MOD-04)
analytics.screen Anthropic → Groq → OpenAI → Gemini Support Analytics (MOD-02)
analytics.report Anthropic → OpenAI → Gemini → Qwen Support Analytics (MOD-02)
warehouse.synthesise Anthropic → Qwen → OpenAI → Gemini Data Warehouse (MOD-03)
pd.analyse / pd.plan Anthropic → OpenAI → Azure → Gemini / Qwen PD Studio (MOD-05)
embedding.encode OpenAI → Local → Ollama Brain search (all modules)
🧠
Anthropic — Claude
Flagship model for deep reasoning, curriculum planning and detailed reports
Cloud API Primary provider
Curriculum mapping CAPS alignment Detailed reports Long-form reasoning Afrikaans support
Powers these INFINITE-AI tasks:
  • Curriculum Map generation (claude-opus-5 — highest quality)
  • MOD-02 Screening & Report writing
  • MOD-04 Toolbox lesson generation & adaptation
  • MOD-05 PD analysis and planning
  • MOD-03 Data Warehouse synthesis
Setup steps
1
Go to console.anthropic.com and create an account with your school email address.
2
Click API Keys in the left sidebar → Create Key. Name it "INFINITE-AI Production". Copy the key — it starts with sk-ant-.
3
Add billing details under Settings → Billing. The Claude API is pay-per-use — a typical primary school uses roughly R200–R600/month at current rates.
4
Paste the key into your gateway .env file (ask your IT coordinator if you don't have access).
ANTHROPIC_API_KEYS= Paste your sk-ant-… key here
ANTHROPIC_BASE_URL= Leave blank — default is fine
💡 Tip: Create two keys — one for development/testing, one for production. That way you can rotate the production key without any service interruption.

OpenAI — GPT-4o
General-purpose workhorse; strong for embeddings and structured data tasks
Cloud API Embeddings
Embeddings (search) Structured outputs Analytics reports Broad model range
Powers these INFINITE-AI tasks:
  • Brain search embeddings — text-embedding-3-large for the Brain's vector search (most important use)
  • Analytics report fallback
  • Data warehouse synthesis fallback
  • Toolbox generation fallback
Setup steps
1
Go to platform.openai.com → sign in or create an account.
2
Go to API Keys → Create new secret key. Name it "INFINITE-AI". Copy the key (starts with sk-proj- or sk-).
3
Add a credit card under Billing. OpenAI requires a minimum top-up (typically $5). Embeddings are very cheap — a full year of Brain search costs under R50.
4
Paste the key into your .env file.
OPENAI_API_KEYS= Paste your sk- key here
OPENAI_BASE_URL= Leave blank — default is fine
⚠️ Important: OpenAI is the only provider that handles Brain search embeddings in the default routing. If you remove OpenAI and have no local fallback, Brain search will degrade. Either keep OpenAI, or set up Ollama with nomic-embed-text as a local fallback.

Groq — LPU Inference
Ultra-fast responses for screening many learner records quickly; generous free tier
Cloud API Ultra-fast Free tier
Screening at scale Fast batch processing Low latency Cost-effective
Powers these INFINITE-AI tasks:
  • MOD-02 Screening — rapidly screens many learner support files (llama-3.1-8b-instant)

Setup steps
1
Go to console.groq.com and create a free account.
2
Click API Keys → Create API Key. Name it "INFINITE-AI". Copy the key (starts with gsk_).
3
No billing required for the free tier — Groq gives generous free limits. For schools running high volumes, upgrade to a paid plan.
4
Paste the key into your .env file.
GROQ_API_KEYS= Paste your gsk_… key here
GROQ_BASE_URL= Leave blank — default is https://api.groq.com/openai/v1
💡 Best for schools on a budget: Groq's free tier handles hundreds of screening tasks per day at no cost. Start here if cost is a concern.

LM Studio
Run models locally on a school laptop or server — no internet required after setup
Local Privacy-first No API cost
Full data privacy No internet required Free to run Curriculum & Toolbox tasks
Powers these INFINITE-AI tasks:
  • Curriculum Map local fallback (qwen2.5-14b-instruct)
  • MOD-04 Toolbox generation local fallback (gemma-3-12b-it)
  • MOD-04 Toolbox adaptation local fallback (gemma-3-4b-it)
Setup steps
1
Download LM Studio from lmstudio.ai and install it on your school server or a capable laptop (needs 16+ GB RAM for the 14B model).
2
Open LM Studio → Discover tab → search for qwen2.5-14b-instruct → download it. This is a one-time download (~9 GB).
3
Click the Local Server tab (left sidebar, looks like a server icon) → Start Server. Note the port number shown (usually 1234).
4
Set the two env vars below. The BASE_URL must point to the machine where LM Studio is running. The key value can be any word (LM Studio doesn't check it).
LMSTUDIO_BASE_URL= e.g. http://192.168.1.10:1234/v1 (your server's IP)
LMSTUDIO_API_KEYS= Any placeholder word, e.g. lmstudio-key
🔐 Privacy advantage: When LM Studio (or Ollama) is used as the primary provider, no data leaves your school network at all — even the de-identified data. This is the highest-privacy configuration. Recommended for Foundation Phase schools.
⚠️ Hardware requirement: The 14B parameter model needs a machine with at least 16 GB RAM, preferably with a GPU. The smaller 4B model (gemma-3-4b-it) runs on 8 GB. Your IT coordinator can advise on which hardware you have.

Ollama
Lightweight local model runner; also provides local embedding fallback for Brain search
Local Offline No API cost Embeddings
Brain search embeddings (local) Offline operation Runs on Linux server Easy model management
Powers these INFINITE-AI tasks:
  • Brain search embeddings — nomic-embed-text (local fallback when OpenAI is down)
  • Curriculum Map deepest fallback (qwen2.5:14b)
  • MOD-04 Toolbox generation deepest fallback (llama3.2:latest)
  • MOD-04 Toolbox adaptation deepest fallback (gemma3:4b)
Setup steps
1
On your school Linux server, run: curl -fsSL https://ollama.com/install.sh | sh — or download the installer from ollama.com for Windows/Mac.
2
Pull the models you need:
ollama pull nomic-embed-text (for Brain search — small, ~270 MB)
ollama pull qwen2.5:14b (for curriculum — larger, ~8 GB)
ollama pull llama3.2:latest (for toolbox — ~2 GB)
3
Ollama starts a server on port 11434 by default. To allow network access: set the environment variable OLLAMA_HOST=0.0.0.0 before starting Ollama.
4
Set the two env vars below. The key can be any placeholder word.
OLLAMA_BASE_URL= e.g. http://192.168.1.10:11434/v1
OLLAMA_API_KEYS= Any placeholder word, e.g. ollama-key
💡 Recommended setup for load-shedding resilience: Run Ollama on a school server with a UPS. Even when Eskom cuts power to internet routers, the AI Brain can keep operating locally with nomic-embed-text for search and smaller models for basic toolbox tasks.

Azure OpenAI — Microsoft Copilot
Enterprise-grade GPT-4o via Microsoft; ideal for schools already on Microsoft 365
Enterprise Cloud API
Microsoft 365 alignment GPT-4o quality Enterprise compliance PD analysis
Powers these INFINITE-AI tasks:
  • MOD-05 PD analysis and planning (gpt-4o via Azure)
  • MOD-04 Toolbox generation fallback
Setup steps
1
Log in to portal.azure.com with your school's Microsoft account (the one that manages Microsoft 365).
2
Search for Azure OpenAI → Create a resource. Choose the region closest to South Africa (currently Sweden Central or East US 2 have the best model availability).
3
Inside your Azure OpenAI resource → Model Deployments → Deploy model → choose gpt-4o. Note the deployment name you choose (e.g. gpt-4o-production).
4
Under Keys and Endpoint, copy Key 1 and the Endpoint URL. The endpoint looks like: https://your-resource.openai.azure.com/openai/deployments/your-deployment
AZURE_OPENAI_BASE_URL= https://yourresource.openai.azure.com/openai/deployments/gpt-4o
AZURE_OPENAI_API_KEYS= Paste your Azure Key 1 here
⚠️ Both vars required: Azure OpenAI only activates when both AZURE_OPENAI_BASE_URL and AZURE_OPENAI_API_KEYS are set. If only one is provided the provider is silently skipped.
§ 03

Best Practices for School Administrators

🔑
Rotate keys regularly
Create a new API key every 3 months and delete the old one. This limits exposure if a key is ever compromised. Keep a record of key names in your school's IT register.
🚫
Never share keys
API keys are like passwords. Don't paste them in emails, WhatsApp groups, or shared documents. The only place a key belongs is in the server's .env file, managed by your IT coordinator.
💰
Set spending limits
Every cloud provider lets you set a monthly spending cap. Set one — even a generous one — so that a runaway process cannot generate an unexpected invoice. Start low and raise it once you understand your usage patterns.
🛡️
Comma-separate for redundancy
Each _API_KEYS= variable accepts a comma-separated list: key1,key2,key3. The gateway pools them and rotates automatically. This gives you redundancy if one key hits its rate limit.
🌐
Local + cloud for resilience
Configure at least one local provider (Ollama recommended) alongside your cloud providers. During load shedding, internet failures, or provider outages, the Brain keeps working locally.
📋
Review usage monthly
Check each provider's dashboard once a month. Unexpected spikes often indicate a misconfigured agent or a test script left running. Early detection prevents unexpected costs.
🔒
Use IP restrictions if available
Some providers (OpenAI, Anthropic) let you restrict a key to specific IP addresses. Set this to your school's public IP if it's static — then even a leaked key is useless from outside your network.
🧪
Test with a staging key first
Create a separate staging API key for testing. Configure it in a test environment before touching the production .env. This prevents accidents during setup.
📞 Need help? Your school's INFINITE-AI coordinator or IT administrator handles all provider configuration. Teachers do not need API keys or access to the .env file — all of this is set up once by the school's technical team and maintained quietly in the background. If you notice that AI features are slow or unavailable, contact your IT coordinator rather than trying to adjust provider settings yourself.
